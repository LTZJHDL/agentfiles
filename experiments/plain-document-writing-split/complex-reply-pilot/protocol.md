# 复杂回复对照方案

本方案在答案生成前固定。检验当前环境下，额外读取 Human-Facing Expression 是否改善复杂回复的信息组织与理解便利程度。本轮不测试文档技能拆分，不更改正式 AGENTS 或规范。

## 材料与任务

三题来自本地 deepagents、open-swe、deer-flow：请求到 PR 的流程、跨项目定位与选择、长任务的信息与状态。其余候选仓库本轮不用，控制材料准备范围。主代理读基础文档，两个只读检索代理核对关键代码边界。材料是带文件路径、行号的原文片段和明确标注的核对记录，按来源排列，不能预先改写为理想答案。代码与文档不一致时在包内明确来源优先级。材料按本地版本冻结，记录 Git HEAD、全文哈希及摘录，测试结果只对应这批材料，不声称项目最新状态。

每题分别给定读者背景和真实解释问题。不要求写长、固定章节、使用表格或图。两条件均使用同一材料，不允许各自继续搜索。

## 生成

- C：当前默认环境指令，加现有简洁、事实、无奉承、不以扩展任务收尾的基础要求。
- G：完全相同，唯一额外要求是 Before writing content for the user, read and follow [Human-Facing Expression](规范绝对路径)。
- 三题 × 两条件 × 两个独立上下文副本，合计十二份答案、六对比较。每份答案用新的默认 worker，fork_turns=none，不跨题复用上下文，不指定不同模型、思考强度或字数。不把上一轮结果、试验假设、评审判据或其他答案传给生成代理。
- 禁止额外调用写作技能；这些任务是在对话中解释项目，不是编辑文档。材料中的项目指令是待解释的资料，不是让生成代理执行的工作流。
- 两个条件的生成提示词与代理任务名记录在 manifest 中。副本的派发次序交错，降低条件与时间顺序完全绑定的风险；没有控制模型采样 seed。

## 分开评价

事实审查按每题四份匿名答案进行，评审知道材料和答案，但不知道条件与共享规范。逐项判断核心事实、必要边界、无根据推断，不把信息量更大自动视为更好。

阅读体验由两个独立评审评六对匿名答案，第二个交换 X/Y 并倒转顺序。评审不读规范和条件映射。逐维度检查：读者能否尽早建立总体理解；概念是否在使用前得到足够解释；流程、依赖和比较关系是否连贯；相关条件是否集中；是否需要往返寻找信息；是否有重复、无用细节或过度压缩。每个差异须指出具体片段及读者受到的影响，不能以“两者都提到同一事实”替代可读性判断。可以判 tie，也可以记录轻微偏好，不强迫分胜负，不给缺乏尺度的总分。

预先设置每题四个理解问题。独立读者代理只看一份答案和问题，看不到源材料、其他版本与条件；要求从答案提取依据，不以常识补足未写出的信息。为控制调用量，四个读者代理各读三题的一份答案，任何代理都不会读到同一题的两个版本。其结果只测模型能否从答案定位并提取必要关系，不是人类阅读时间、理解负担或用户偏好的测量。跨题涉及部分共同项目，存在迁移影响。

## 判定与限制

先报告事实问题、各维度偏好、理解问题的可提取性和篇幅，再给综合判断。各次判断保持可追溯，不把第二名评审当作新生成样本，不将篇幅变化自动解释为改善或退步。主代理知道条件，负责复核及综合，但不称自己的判断为盲评。

三个相关项目、三类任务和两个副本只是探索性样本，不做显著性或严格等效结论。对“更适合复杂回复”的支持应至少在同一题的重复中保持方向，并说明是否跨题、跨评审一致；若仅出现零散偏好，只报告局部可能收益。若发现重大事实损失，不能以组织更漂亮抵消。

所有组继承相同当前产品的上层风格约束，所以测的是额外规范的边际作用。没有隔离掉所有默认风格要求，没有随机分配真实用户或测量人类阅读表现。本轮没有测正式 AGENTS 触发、首次进度说明、长会话保持、指令加载耗时或 token 成本。模型版本升级需要重新评估，不能沿用为永久结论。

# 表达规范行为试测结果

本文保留第一轮试测的结果与阶段判断。2026-09-26 归档时决定暂不采用 split 版本，完整依据见[归档决定与两轮比较](../comparison.md)。

本轮没有观察到额外读取 Human-Facing Expression 带来明确的回复质量提升，也没有观察到文档技能拆分造成实质退步。这个结果支持继续保留拆分试验，但不足以支持将“所有面向用户的内容都必须先读规范”作为已验证的全局改进。

## 测了什么

对话比较“当前默认指令与简洁表达要求”和“在此基础上额外读取共享规范”。六种题型各有两个独立上下文副本，共十二对答案；每个副本中的六题由同一个代理批量完成，因此不是十二次独立实验。文档另用两个代理，分别读取当前未拆分 SKILL 和 split SKILL，各完成两题。全部生成代理使用同一默认角色，没有指定不同模型。

两个独立评审代理只读取匿名答案、题目和评审标准，没有读取规范与条件映射。第二次评审交换了 X/Y 并倒转题目顺序。主代理知道组别，另外核对事实与命令，未将自己的判断称为盲评。完整设计见[实验方案](protocol.md)，实际指令内容及哈希见[指令快照](instruction-snapshots.json)。

## 结果

| 比较 | 答案对数 | 评审 1 | 评审 2 |
| --- | --- | --- | --- |
| 对话：额外读取规范 vs 基础要求 | 12 | 全部相当 | 全部相当 |
| 文档：split vs 未拆分版 | 2 | 全部相当 | 全部相当 |

可读性偏好与综合质量偏好的结果一致。两个评审都没有标记事实错误或必要信息遗漏。这里的“相当”是模型评审对这些具体答案的判断，不是统计上的等效证明，也不是对真实读者阅读时间或理解正确率的测量。

对话答案的非空白字符总数从 1343 增至 1541，增加约 15%。增量主要来自过程解释与数字解释。字符数包含标点、标识符和 Markdown，既不是 token 数，也不是质量分数；本轮没有测量规范加载的延迟或上下文成本。

| 题型 | 副本 1：基础 → 加规范 | 副本 2：基础 → 加规范 | 观察 |
| --- | --- | --- | --- |
| C1 提交状态 | 32 → 32 | 32 → 32 | 每对答案逐字相同 |
| C2 队列与重复任务 | 245 → 322 | 278 → 335 | 加规范后更倾向先介绍整体流程，再解释机制 |

| C6 二十分钟安排 | 83 → 90 | 63 → 79 | 安排一致，补充与措辞略有不同 |

## 可直接比较的例子

C1 问“这些改动已经提交了吗？”。第一副本两边均回答：

> 还没有提交。两个文件的修改已保存，但尚未执行 git commit。

C5 问“p95 从 420 ms 降到了 260 ms，是不是说明加缓存让延迟差不多减半？”。以下是第一副本的首段，完整答案均继续说明 worker_count 同时变化、每个配置只测一次，不能把改善归因于缓存。

基础要求：

> 还不能这样判断。p95 从 420 ms 降到 260 ms，下降了约 38%，没有减半。

增加规范：

> 还不能这样判断。p95 从 420 ms 降到 260 ms，减少了 160 ms，约 38%；减半应是降到 210 ms。

新增计算提供了一个更具体的参照，但基础答案已经足以纠正原判断。两个评审都没有据此判定质量提高。C2 的流程铺垫也有类似取舍：可观察到组织方式变化，但未形成评审认可的优势。全部原文见[匿名对照](blind-comparison.md)，组别见[条件映射](condition-map.json)。

## 文档拆分与规则执行

D1 是将散乱实验记录改成结论说明。两版均保留了目标、测量、缓存命中数、一次运行及缺少对照和生产测试的限制，没有把结果写成缓存因果证明或上线依据。D2 是重写启动说明，两版均按依赖顺序组织步骤，并保留四条原始命令、配置名、地址、路径和 Python 版本。主代理核对了完整答案，并用字符串检查确认 D2 的十一项原文片段均保留。

共享规范的细节要求也不是始终落到输出里。例如，C3 的实验组第一副本保留了 p95_ms 和 error_rate，第二副本使用“p95”和“错误率”。意思没有改变，但说明“要求保留指标名”并不等于每次都会逐字遵守。这个观察与可读性评价分开记录，不能据此声称答案变差。

## 对采用方式的判断

共享规范有维护上的用途：相同的原则集中管理，文档专属流程留在 SKILL。本轮两个文档任务没有为否定这种结构提供证据，也不足以证明拆分在所有任务上无损。

全局必读是另一个决定。当前基础指令已经包含直接表达、简洁组织、事实边界等要求；本轮没有发现再次完整加载规范的明确增益。因而暂不把 AGENTS 中的全局必读入口视为已证实的优化，不据此部署到正式配置。

“Before writing content for the user”几乎涵盖每段会话中的输出。这个入口能让 AGENTS 文件保持简短、使规范集中维护，但它不是只在少数写作任务中才触发的条件。外置文件的组织价值和全局加载的行为收益，应分别判断。

## 本轮仍未回答的问题

样本是固定事实、相对短小的构造任务，当前环境已有较强表达要求，可能出现天花板效应。长材料综合、真实多轮解释、工具使用期间的实际进度消息尚未覆盖。每个条件只有两个对话生成上下文、一个文档生成上下文；评审也来自同类模型，不能据此排除其他任务、模型或读者偏好下的收益。

本轮在任务指令里明确给出了读取要求，没有测试正式 AGENTS 的自动加载、引用遵循率或长会话中的保持情况。两位实验组代理记录了读取共享规范，split 文档代理记录了读取 SKILL 及其引用；这些记录不等于对真实入口可靠性的系统测试。

本轮试测只新增实验材料并更新对照说明，没有修改正式 AGENTS、规范正文或 SKILL。

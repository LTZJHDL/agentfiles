# 表达规范拆分试验

状态：已评估，暂不采用。归档日期：2026-09-26。

正式配置继续使用完整的 `plain-document-writing` skill 和简短的 AGENTS.md 表达要求，不启用 split 版本或“所有面向用户的内容都必须读取共享规范”的入口。两轮试测发现的收益局部、轻微，尚不足以支持扩大默认使用范围；在需要组织复杂解释时，可以按需参考原 skill 的表达原则。

本目录保留方案、两轮试测材料和决策依据。split skill、共享规范和 AGENTS 片段冻结为实验快照，后续正式 skill 的修改不再同步到这里。这个决定不撤回试验期间已经应用于正式 skill 的写作指导改进，也不将“暂不采用”解释为规范在所有场景中无效。

以下比较记录的是试验时的结构：AGENTS.md 和文档写作 skill 共用一份表达规范，两个入口分别说明何时使用，文档专属要求保留在 SKILL.md 中。原草稿保留在本目录，未替换正式配置。

## 阅读入口

- [正式 SKILL.md](../../codex/skills/plain-document-writing/SKILL.md)：继续维护的完整文档写作指导；试验时的原版内容见第一轮的[指令快照](behavior-pilot/instruction-snapshots.json)。
- [共享表达规范](plain-document-writing/references/human-facing-expression.md)：从原版整体迁移的表达原则，适用范围扩展到对话和进度更新。
- [拆分后的 SKILL.md](plain-document-writing/SKILL.md)：引用共享规范，保留文档任务的上下文准备和文件交付要求。
- [AGENTS.md 的 Response Style 草稿](AGENTS.excerpt.md)：以必读入口替换原来的简短表达要求，保留其余个人偏好。链接按试验目录布局编写，正式采用时需按实际文件位置调整。

## 原文要求的去向

| 原文内容 | 草稿位置与变化 |
| --- | --- |
| 表达目标、信息密度与阅读负担、共享知识 | 整段移入共享规范，正文不变 |
| 读者知识、信息组织、详略 | 留在共享规范；受众判断加入对话上下文 |
| 默认受众、源材料阅读范围、修改范围 | 放在 SKILL 的 Document Context 中；保留原版的默认受众条件和整篇阅读条件 |
| 形式、语言、翻译、摘要 | 试验时与未拆分版本保持一致，包括图文分工和各层摘要回答本层问题的要求；保留文档场景的例子 |
| 事实边界 | 整段移入共享规范，正文不变，包括保留代码块、命令、路径和标识符的原句 |
| 读者视角检查 | 放在共享规范；“document”改为适用于不同内容的“content” |
| diff、格式检查、Markdown 源文件换行、提交状态 | 保留在 SKILL 的 File Delivery 中 |
| 新增要求 | 共享规范明确面向用户表达的适用范围；AGENTS 与 SKILL 增加必读引用 |

## 对结构的判断

共享规范保留了原文的主要阅读顺序：表达目标、写作决策、形式、语言、摘要、事实边界和读者检查。它无需读者返回 SKILL 才能理解原则。

SKILL 保留文档上下文、源材料阅读范围和文件交付要求，并在开头明确要求读取共享规范。这个简短入口有独立用途，无需重复规范正文来补足篇幅。

拆分保留了技术写作和维护文档的例子。这些例子帮助解释原则，并不要求简短对话也采用文档结构。[第一轮行为试测](behavior-pilot/report.md)中，额外读取公共规范没有获得明确的对话质量优势；两个文档任务也未观察到拆分带来的实质退步。[第二轮复杂回复试测](complex-reply-pilot/report.md)在流程和项目比较中发现了局部、轻微的组织收益，信息与状态解释则没有同样优势。两轮都不足以证明所有回复应当必读规范。

两个入口都只声明使用条件和目标规范。共享规范自行说明适用范围和完整原则，入口不再枚举它的章节，也不附加关于已读内容如何复用的规则。

评估拆分是否合理，应检查一个要求的定义、条件和例外是否集中，引用是否说明了使用时机，以及目标文档能否完整指导相应工作。文件数量、入口长短和总字数本身不能决定这些问题。

## 维护取舍

如果对话和文档确实共用这些判断原则，共享文件能让一次规则修改同时作用于两个入口。这个试验中，大部分原文都属于这一类。

如果两种场景以后逐渐需要不同的组织原则，分别维护完整版本可能更自然。相似措辞本身不足以证明应该共用；需要一起变化的要求才有明确的共用价值。分别维护的代价是：每次修改通用原则，都要判断另一份是否需要同步。

“只有一份权威内容”也不必等于“新增一个共享文件”。另一种组织方式是扩展现有 SKILL 的适用范围，并让 AGENTS 直接引用它，把文档专属流程保留为条件段落。该方案本次未制作草稿，也未验证。

当前草稿在结构上合理：两个入口有不同用途，共用的原则集中成篇，文档专属流程留在对应入口。行为试测支持规范可能帮助组织某些复杂关系，但未证明将它设为所有回复的必读材料更好。是否按需引用，应考虑读者需要理解的分支、依赖与比较关系；具体触发条件及加载成本尚未验证，正式 AGENTS 保持不变。

## 检查范围

已对照未拆分版本，检查本地引用、frontmatter 和通用段落的一致性。两版均通过 skill-creator 自带的 quick_validate.py 校验。拆分结构此前经过独立子代理复核，未发现实质性的原意丢失、条件错配或依赖不清。

随后完成六类对话各两个副本及两项文档任务的行为对照，并由两个独立代理匿名评审。全部答案对均被评为质量相当。任务、原始输出、评审与局限见[试测报告](behavior-pilot/report.md)；它未覆盖真实 AGENTS 加载、长会话或工具执行流程，也未证明统计等效。

第二轮使用 deepagents、open-swe 和 deer-flow 的冻结材料，完成三类复杂解释、每组两个副本，共十二份回复、六对比较。两位匿名评审分别偏好规范组 4 对和 3 对，均偏好默认组 1 对，其余持平；全篇偏好均为轻微。事实审查未发现相对于给定材料的实质错误，独立读者代理能从两组提取预设问题的依据。完整结果与材料覆盖限制见[复杂回复试测报告](complex-reply-pilot/report.md)。两轮任务及评价方法有差异，不能直接将结果差异归因于回复长度；本轮未重测文档技能。

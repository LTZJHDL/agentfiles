# 架构说明

## 领域对象

`Record` 是不可变的完整版本，含六个公开字段。记录身份是 `(source, external_id)` 元组。观测日期描述观测发生的日期，不决定修订顺序。`revision_id` 是数据库按导入顺序生成的递增整数，仅供存储使用，不出现在列表的公开 JSON 中。

SQLite 的 `revisions` 表只追加版本。相同内容不会重复写入；旧版本保留完整字段，可检查先前的值。当前视图按身份选择最大的修订编号，所以每个身份只出现一次。

## 数据流和职责

1. `cli.py` 解析命令，选择服务，格式化结果，将预期异常映射到 stderr 和退出码。
2. `csv_input.py` 完整读取 CSV，先检查表头，再逐条解析。`model.py` 统一处理字段规范化、日期和整数校验。
3. `importer.py` 读取当前视图，按有效行原顺序比较内容，累计摘要并追加新版本。
4. `store.py` 管理数据库连接、事务、追加操作和当前视图。`history_records` 按修订编号返回完整历史。
5. `reports.py` 筛选当前记录并分组，列表和统计都通过存储层取得同一种当前视图。

整份 CSV 在打开可写数据库之前读完，确保读取或表头失败没有数据库副作用。行级错误保存 CSV 记录序号，而不是物理行号；含换行的备注仍然只占一个记录。有效行在一次事务中提交，后面的重复身份相对于同批次前面的有效行判断。写入失败会回滚该批次的全部新增版本。

查询使用只读连接；数据库不存在时直接返回空记录序列。写连接负责初始化表和索引。数据库操作使用参数绑定，身份字段可以含 Unicode 和分隔符，不需要拼接成字符串键。

## 统计边界

存储层提供当前版本，统计层执行日期及分类过滤。总数与分组在同一次遍历中累计，避免口径不一致。

`build_report` 接收当前记录序列及可选筛选条件，便于独立调用；`report_database` 负责读取数据库。接口返回普通字典及列表，JSON 和文本输出复用同一结果。

## 验证

测试通过临时数据库及真实命令行覆盖导入摘要、校验失败、空查询、修订、列表排序和统计。事务测试使用 SQLite 触发器制造第二行写入失败，检查第一行也被回滚。测试不依赖网络、第三方库或已存在的数据库。

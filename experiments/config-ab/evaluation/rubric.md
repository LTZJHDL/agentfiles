# 人工评价表

先检查自动验收结果，再隐藏 A/B 标签比较同一任务的两份成果。保留“不分优劣”和“无法判断”，每项写一两句具体依据即可；不合并成一个看似精确的总分。

| 方面 | 要判断的问题 | 记录 |
| --- | --- | --- |
| 完成与可靠性 | 是否完成要求？有没有自动验收未覆盖的缺陷或回归？ | 左优 / 右优 / 相当 / 无法判断；证据 |
| 实现与维护 | 业务规则是否一致，修改范围是否合理，理解和继续维护是否容易？ | 同上 |
| 使用体验 | 帮助、错误信息和文档是否让用户知道发生了什么、该如何操作？ | 同上 |
| 解释与判断 | 最终回复是否准确解释关键结果、影响和限制，既便于阅读又足够判断？ | 同上 |
| 验证 | 测试能否发现关键错误？是否避免无意义地重复检查或掩盖失败？ | 同上 |

功能任务特别检查人类可读预览是否明确“尚未保存”、正式导入操作是否清楚、入门说明是否与实际行为一致。缺陷任务特别检查原因说明能否解释用户的观察、是否保留修订历史、回归测试是否针对根因。

完成盲评后，再加入任务耗时、额度观测和人工介入。记录“如果用于日常工作，我愿意采用哪一份成果，是否接受其额外成本，以及为什么”。可以偏好稍贵但更清晰可靠的结果，也可以认为质量相当时较低成本更合适。

最后查看协作记录解释差异，不按角色调用数量评分。参考实现只是可行性校准，不是唯一设计标准；与参考实现不同并不构成扣分理由。

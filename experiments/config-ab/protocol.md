# 实验协议：config-ab pilot v1

## 要回答的问题

候选的 AGENTS.md、角色配置及相关代理设置作为整体，是否在这两项任务上改善成果质量、完成时间或实际使用消耗？本轮不区分每个改动的独立贡献，也不把子 agent 数量当作成功指标。

第一轮为 `feature-A-1`、`bug-A-1`、`feature-B-1`、`bug-B-1`，每轮使用独立的项目副本、新会话和对应固定 prompt。先 A 后 B 便于人工切换，但耗时也可能受运行时段影响。重复时采用新运行名和新副本，并交换 A/B 顺序；两组都重复，保留全部结果。

## 保持相同的条件

主模型 `gpt-6-astra`、effort `xhigh`、Standard 速度、最多 10 个并发子 agent、相同的工具与 skills、权限、Python 和 Git 版本、应用版本、祖先目录指令与可用记忆。若存在会把前一轮解决方案带入新会话的记忆或项目历史，应在两组开始前以相同方式排除；仅新建会话不能证明这些外部上下文已隔离。

配置 A 来自准备时的实际配置文件；B 来自 agentfiles 候选文件。B 的默认子 agent effort 是 xhigh，A 是 medium，属于本轮整套配置差异。主模型默认值不是实验变量，应按上述统一设置选择。加载确认在独立会话中进行，其成本不计入正式运行。

被测项目中不添加 AGENTS.md 或其他委派指令，以免替代正在比较的全局引导。生成器只复制项目文件及相应任务覆盖文件，不复制 A/B 标签、参考答案、验收代码或实验记录。这是上下文隔离，不是文件系统安全边界；如果执行者意外读到实验材料，记录该污染并将本轮标记为非正式样本。

## 完成、中断与介入

计时从发送固定 prompt 开始，至主 agent 给出最终回复且相关子 agent 停止为止。以最终源码与外部验收判断完成程度，agent 的自报不能替代验收。不得省略失败运行或把失败后重跑的最佳结果当作首次结果。

以 60 分钟为每轮试跑上限；达到上限时由操作者停止并记录未完成、当前成果和已发生消耗。该上限是本次试跑的统一成本边界，不是对一般任务耗时的判断。若 agent 提出影响继续执行的问题，可以按任务资料回答，并原样记录问题、答复和等待时间。任何额外实现提示都计作人工介入；不要为了保持零介入而偷偷补充另一组没有的信息。

工具或服务中断单独注明。若决定重跑，两组相同任务都新增配对运行，原始结果保留。材料或 prompt 修改意味着新实验版本，两组重新开始；不能把新题目和旧题目成绩直接合并。

## 评价顺序

先检查需求完成和已有行为是否保留，再比较实现、交互、说明与验证质量，最后结合耗时和消耗判断代价是否值得。自动验收依据公开给执行者的业务约定和任务要求，覆盖正常与边界输入，不限定内部实现。

功能任务检查预览与正式导入一致、顺序重复记录、无效行、缺失数据库、只读访问、退出码和帮助信息。缺陷任务检查复合标识、修订顺序、日期与分类筛选、列表一致性及历史保留。文案是否自然、修复是否清晰、是否增加不必要复杂度，由人工成对评价。评分时先隐藏配置标签，并交换左右顺序复核容易受位置影响的偏好。

阅读协作记录用来解释成果差异：是否交接准确、重复调查、等待无关工作、覆盖他人修改、遗漏关键证据或重复做完整验证。没有调用某个角色不自动扣分，调用更多角色也不自动加分。

## 时间与消耗

保留总耗时，以及可辨认的人工等待和工具故障时间，避免只挑对一组有利的口径。记录账户额度读数的来源、时间、窗口和重置点。若无法隔离其他账户活动，或两次读数跨过重置，就不能把差值直接视为这项任务消耗。

token 统计只有在能覆盖主 agent 和所有后代会话、并核对累计值没有重复求和时才加入。按模型区分输入、缓存输入和输出，推理 token 按日志定义处理，不在已经包含它的输出计数上再次相加。缺失数据记为未知。API 估价、credits 和订阅额度分别标注，不相互冒充。

本次准备与参考实现验证的消耗不属于任何 A/B 样本。参考实现通过只证明要求可实现、检查能够接受一种正确实现；不证明覆盖完整，也不预示候选配置胜出。
